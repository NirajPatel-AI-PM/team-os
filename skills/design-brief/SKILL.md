# Design brief

Read the spec first. Then write `design/YYYY-MM-DD-<topic>.md` with:

1. **The user and the moment.** Who is using this, what they were doing just before, and what they need to finish.
2. **The outcome.** Copied from the spec. The design succeeds when this moves.
3. **Constraints.** The design system components to use, accessibility requirements, and every state: empty, loading, error, partial, full.
4. **Content.** The real words, not placeholder text. Flag any copy that needs review.
5. **Open questions for the designer.** What the spec does not decide.

Do not produce a visual design. A designer does that, with Claude as a collaborator, from this brief.
